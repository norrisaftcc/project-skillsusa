## Client

The fictional Pinewood Housing Resource Navigator helps visitors on shared or slow computers understand the services available. The site must never ask for private financial or identity data. **Main visitor task:** find a service type, read its schedule and find a way to contact it.

## Client-approved facts

- General office: Monday–Thursday, 9:00 a.m.–4:00 p.m.
- General contact: help@pinewood.example

| Service | Type | Schedule | Email |
|---|---|---|---|
| Rental Guidance | Information | Weekdays 9:00 a.m.–noon | rental@pinewood.example |
| Budget Coaching | Education | Tuesday 1:00–3:00 p.m. | budget@pinewood.example |
| Accessibility Resources | Assistance | Wednesday 10:00 a.m.–2:00 p.m. | access@pinewood.example |
| Documentation Help | Assistance | Thursday 11:00 a.m.–3:00 p.m. | docs@pinewood.example |

## Acceptance criteria

1. Before coding, write five discovery questions and three testable requirements.
2. Clear, responsive navigation and four accurate service cards.
3. An accessible filter by resource type, with a count and an empty state.
4. A statement that the page is for information only and visitors must not send private details.
5. Every page behavior works at 320 px and with the keyboard alone.
6. Eight tests, a defect report and a known limitation in `EVIDENCE.md`.
7. An explanation of scope: what the site gives, what it cannot check, and what stays outside the project.

## Hand in

Hand in a small-screen sketch, the source code, client notes, a test table and a two-minute demonstration. The coach can give two separate changes after code freeze. Record each change and retest the features that worked before.
