# Web Development | 12-Week SkillsUSA Preparation Plan

2026–27 working curriculum | October 30, 2026

## Purpose and source boundary

Develop independent, testable skill in client discovery, semantic markup, responsive CSS, accessible JavaScript, debugging and defending technical decisions. All times, scores and practice prompts are created by instructors, not official 2027 SkillsUSA rules. The 2026 national recap describes live client discovery, hand-built sites, paper wireframes, client changes and interviews. Confirm the current 2026–28 standards through SkillsUSA Pathful and NC-specific instructions before formal contest rehearsal.

## Twelve-week teaching sequence

| Week | Content |
|---|---|
| 1 | Client discovery, acceptance criteria, mobile wireframes; original Community Resource Desk baseline. |
| 2 | Semantic HTML, landmarks, heading structure, navigation, accessible forms. |
| 3 | CSS cascade and specificity, Grid, Flexbox, responsive layout at 320/768/1280px. |
| 4 | Accessible DOM interaction: filters, event listeners and disclosure widgets. |
| 5 | Images, alternative text, optimization, data integrity and search behavior. |
| 6 | Debugging, browser tools, regression testing, defect documentation. |
| 7 | Full mock A: Riverbend Neighborhood Festival, a four-activity responsive schedule with category filtering. |
| 8 | Mock A change request, regression tests and a short judge-style explanation. |
| 9 | Full mock B: Cedar Lab Workshop Directory, six workshops with combined topic and title search. |
| 10 | Mock B change request, 40-question knowledge check, targeted remediation. |
| 11 | Mock C: Pinewood Housing Resource Navigator, more open-ended planning and privacy-sensitive UX. |
| 12 | Comprehensive rehearsal, scoring calibration, documentation and readiness decision. |

## Weekly cadence

Meeting A: teach a small concept, then use a 15–45-minute skill clinic. Meeting B: one realistic visitor task, independent coding, timed evidence collection, brief interview and focused revision. Use the same observable rubric across builds.

## Student evidence

Each session records the audience, requirements, small-screen wireframe, code artifact, elapsed time, verified tests, a failed test and repair, an unresolved issue and a two-minute explanation. Anonymous session IDs are sufficient in the offline hub.

## Instructor scoring

Local rubric: client requirements and working behavior 25; accessible semantics/keyboard access 20; responsive layout 20; planning/client reasoning 15; testing and repair 10; communication/handoff 10. These are NOT official event weights.

## Post-assessment action

After each mock, identify the two largest defect classes. Assign specific skill labs, run a short repair attempt and retest the same behavior. Do not add arbitrary features when the core task remains broken.
