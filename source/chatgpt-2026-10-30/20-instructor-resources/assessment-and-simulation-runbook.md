# Web Development | Instructor Assessment & Simulation Runbook

Working coach guidance | October 30, 2026

## Local rubric (100 points, NOT official competition weighting)

- Client requirements and working behavior — 25.
- Accessible semantic HTML and keyboard operation — 20.
- Responsive layout and legible presentation — 20.
- Planning and client decision making — 15.
- Verification and defect repair — 10.
- Communication, explanation and handoff — 10.

Score with visible evidence. Distinguish required behavior from visual taste. Record a two-line reason for each domain. Ask two coaches to score the same sample before assessment and resolve large disagreements.

## Sequence

1. Before meeting: confirm current event requirements in Pathful and NC materials; distribute only student materials.
2. Opening: student reads brief, asks client questions and sketches mobile hierarchy.
3. Build: student implements independently using the announced local conditions; coach records observations but does not provide a finished solution.
4. Code freeze: save files, test browser at 320px, 768px and 1280px; test keyboard and console.
5. Timed change: release a coach-only twist card and require regression testing of previously working features.
6. Interview: select 4–6 questions from the bank and have the student connect requirement → code → observable test.
7. Debrief: score rubric, identify two recurring errors, assign an exact LAB and retest.

## Client change cards — instructor only

- **A | 25-minute change:** heavy rain moves Pondside Yoga to Community Center Room A and Community Concert to Auditorium; alert users without changing other activity facts.
- **B | 30-minute change:** Intro to Python is CANCELED. Keep item visible and searchable, display canceled state, exclude from active-workshop count and do not invent a date.
- **C1 | 20-minute change:** produce a useful print layout for service details and contact.
- **C2 | 20-minute change:** office closes at 2:00 p.m. Thursday while service-specific appointment information remains as originally listed.

## Interview prompts (selection)

- Who is the primary visitor and their first task?
- Show a requirement in the brief, its implementation and a test.
- Demonstrate the full workflow without a mouse.
- Why did you use these semantic landmarks and heading levels?
- How does a filter update both visible records and a live status message?
- How does the layout handle narrow screens without overflow?
- What failed in testing? Describe root cause and retest.
- How would you change the project safely if the client alters a core fact?
- What is deliberately out of scope?

## Content and technical checks

Exact approved facts, complete links, announced filter count, no errors, visible keyboard focus, consistent heading hierarchy, labeled fields, meaningful alternatives, responsive design, and evidence of regression tests. Automated checks are limited and do not certify WCAG.

## Materials available in downloadable complete pack

Ten lab prompts; three original scenarios; two instructor-run reference websites with plain HTML/CSS/JS; student starter files; 40-item knowledge check and separate answer key with explanations; coach scoring CSV, evidence template CSV, interview bank, remediation map and offline practice hub.

## Official scope caution
