# Practice lab / recommendations

Rehearse the work, not just the syntax.

The corpus is most useful as a training playbook. These activities are suggested practice, not additional competition rules.

## Student lens: Build and explain together

Choose a design lead and development lead for each mock event, then swap next time. Cross-training lets each teammate explain the whole project and help when the other gets stuck.

## Facilitator lens: Coach through observable work

Ask to see a user task completed, a keyboard test and the reason for a layout choice. Use consistent rubric feedback; invite an alumnus or local professional to act as a mock client.

## A four-hour practice session

Suggested exercise: build a responsive site for a fictional North Carolina community repair café. The official event may use a different format, duration and subject. (The brief is in [mock-brief-repair-cafe.md](mock-brief-repair-cafe.md).)

| Time | Step | Work |
|---|---|---|
| 0:00–0:20 | Read the client brief | Identify the audience, required content and most important user task. Ask what a successful result lets someone do. Turn the brief into an acceptance checklist. |
| 0:20–0:50 | Plan the experience | Sketch the page structure and navigation on paper, including a narrow-screen view. Agree on typography, colors, file organization and how teammates will hand off changes. |
| 0:50–2:50 | Build a complete first version | Use semantic HTML, responsive CSS and purposeful JavaScript. Implement the main user journey first. Keep an asset-source log and brief notes about decisions. |
| 2:50–3:30 | Test and refine | Check keyboard use, focus, form labels, contrast, narrow screens, broken paths and core interactions. Validate markup, fix high-impact defects and record what you checked. |
| 3:30–4:00 | Explain the result and debrief | Both partners demonstrate the site and explain a design choice, a technical decision and a tradeoff. Review the sample rubric, then choose one improvement for the next session. |

**Optional variation: a client change request.** Halfway through a later practice, change a service, add an announcement or revise a layout requirement. Use this to practice scope decisions and maintainable code. A surprise “twist” is not confirmed for NC 2027.

## Evidence worth keeping

- The brief with a check against each requirement.
- A sitemap or wireframe and a note explaining changes.
- An asset-source log and readable project structure.
- A test log with bugs found, fixes and remaining limitations.
- A short reflection from each teammate.

Confirm the event’s actual delivery requirements before submitting anything.

## A flexible seasonal rhythm

- **Autumn:** short builds, web fundamentals and paired explanations.
- **Winter:** timed team simulations, accessible interactions and unfamiliar client briefs.
- **Before state:** verify procedures, test equipment and rehearse the full workflow.
- **After state:** use feedback to prepare for national requirements if advancing.

## A practical quality check

**Can a visitor use it?**

- Navigate with Tab, Shift+Tab and Enter. Keep focus visible.
- Check text alternatives and form labels.
- Test a narrow screen and zoom without losing functionality.
- Try every required link, button and form path.

**Can the team explain it?**

- Connect the layout to the audience’s main task.
- Explain a CSS or JavaScript decision in your own words.
- Show a bug you found and how you verified the fix.
- Explain the tradeoff you made to meet the time limit.

## Learning references and vocabulary

Keep primary references close:

- MDN web development lessons: https://developer.mozilla.org/en-US/docs/Learn_web_development
- W3C WCAG 2.2: https://www.w3.org/TR/WCAG22/
- W3C HTML checker: https://validator.w3.org/nu/

Practice access does not establish permission to use a resource during competition.

| Term | Meaning |
|---|---|
| UX / UI | User experience / user interface: how the website works for people and how they interact with it. |
| Wireframe | A simple plan of content, navigation and layout before visual polish. |
| Semantic HTML | Elements chosen for meaning, such as a button for an action and a heading for a section title. |
| PDT | SkillsUSA Professional Development Test, separate from a technical knowledge test. |
| SLSC / NLSC | State / National Leadership and Skills Conference. |
